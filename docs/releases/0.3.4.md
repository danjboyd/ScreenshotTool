ScreenshotTool 0.3.4 is a bug-fix release. Captures open with their own title, command results always show in a notice over the image, Redact Emails and Phone Numbers always says how it went, and the Linux AppImage gets rounded window corners and a window shadow.

## Upgrading

Use Check for Updates, or wait for the automatic check.

## Changes

- **Take Screenshot (all platforms):** a new capture opens in a window titled with the time it was taken, for example "Screenshot 2026-11-03 at 10.15.32", and Save As and Save Project offer that name. Captures used to open as "Pasted Image". Paste as New Image still opens as "Pasted Image" (#332, #339).
- **Redact Emails and Phone Numbers (all platforms):** when nothing is redacted, it now says why: "No text found in the image" when no text could be read, or "No email addresses or phone numbers found" when there's text but nothing matched. The two cases used to share one message. Starting Copy Text or Redact again while a read is still running now says "Still reading text…" instead of doing nothing (#333, #340).
- **Command results (all platforms):** the result of a command you just ran (Copy, Copy Text, Redact Emails and Phone Numbers, Share, Crop, Paste as New Image, Take Screenshot, a custom action) now always shows in the notice over the image, even with the status bar on. It used to be short text in the status bar that was easy to miss. Ongoing status, such as "Reading text…" and the image's size, stays in the status bar (#344).
- **Linux AppImage:** windows have rounded corners and a shadow, as in the Adwaita theme. The AppImage now carries the Adwaita theme's libs-back patches, backported to libs-back 0.32 (#343). <!-- TODO(screenshottool-linux): wording and any issue number for the corners and shadow -->

## Known issues

- **Linux:** the About panel can open behind the main window. Bring it forward from the Activities overview.
- **Windows:** Email reports that the share is done as soon as you click it, not when Outlook's message window returns. A failure later in Outlook may go unreported.
- **Linux on Wayland:** the share sheet's Copy writes only the X11 clipboard. The toolbar's Copy button writes to both clipboards.
- **Windows 11:** pressing Esc in Open With's chooser doesn't bring the share sheet back (libs-sharing#26).

The macOS app is ad-hoc signed and not notarized, so Gatekeeper asks before the first launch. See [Install ▸ macOS](https://github.com/danjboyd/ScreenshotTool#macos) in the README, or "Opening an unsigned app.txt" in the DMG. The Windows MSI is unsigned: click "More info → Run anyway" in Windows SmartScreen.
