ScreenshotTool 0.3.4 is a bug-fix release. Captures open with their own title, command results always show in a notice over the image, Redact Emails and Phone Numbers always says how it went, and the Linux AppImage gets rounded window corners and a window shadow.

## Upgrading

Use Check for Updates, or wait for the automatic check.

## Changes

- **Take Screenshot (all platforms):** a new capture opens in a window titled with the time it was taken, for example "Screenshot 2026-11-03 at 10.15.32", and Save As and Save Project offer that name. Captures used to open as "Pasted Image". Paste as New Image still opens as "Pasted Image" (#332, #339, #350).
- **Redact Emails and Phone Numbers (all platforms):** when nothing is redacted, it now says why: "No text found in the image" when no text could be read, or "No email addresses or phone numbers found" when there's text but nothing matched. The two cases used to share one message. Starting Copy Text or Redact again while a read is still running now says "Still reading text…" instead of doing nothing (#333, #340).
- **Command results (all platforms):** the result of a command you just ran (Copy, Copy Text, Redact Emails and Phone Numbers, Share, Crop, Paste as New Image, Take Screenshot, a custom action) now always shows in the notice over the image, even with the status bar on. It used to be short text in the status bar that was easy to miss. Ongoing status, such as "Reading text…" and the image's size, stays in the status bar (#344, #348).
- **Status bar (all platforms):** while an image has unsaved changes, the status bar says "unsaved" in place of the file size, since the file on disk no longer matches the image. Saving shows the file's new size (#348).
- **Recents (Windows):** the dates under recent images are in local time. They used to be in UTC (#350).
- **Linux AppImage:** under GNOME, windows, dialogs and menus have rounded corners and a shadow, as the Adwaita theme intends. The AppImage now carries the theme's libs-back patches, backported to libs-back 0.32. 0.3.3's were square, with no shadow (#343).
- **Linux AppImage:** Paste as New Image and Take Screenshot did nothing in the AppImage on systems with GNUstep installed, from a distribution's packages or in /usr/GNUstep, when an image was already open. They opened the new window through the system's GNUstep, which couldn't start the AppImage's. If a new window ever fails to open, ScreenshotTool now says so (#346).
- **Linux AppImage:** Copy works the same on systems with GNUstep installed. While another GNUstep app ran, the AppImage copied through that app's older clipboard service, and other apps didn't get the image as PNG. It now always uses its own (#346).

## Known issues

- **Linux:** the About panel can open behind the main window. Bring it forward from the Activities overview.
- **Windows:** Email reports that the share is done as soon as you click it, not when Outlook's message window returns. A failure later in Outlook may go unreported.
- **Linux on Wayland:** the share sheet's Copy writes only the X11 clipboard. The toolbar's Copy button writes to both clipboards.
- **Windows 11:** pressing Esc in Open With's chooser doesn't bring the share sheet back (libs-sharing#26).

The macOS app is ad-hoc signed and not notarized, so Gatekeeper asks before the first launch. See [Install ▸ macOS](https://github.com/danjboyd/ScreenshotTool#macos) in the README, or "Opening an unsigned app.txt" in the DMG. The Windows MSI is unsigned: click "More info → Run anyway" in Windows SmartScreen.
