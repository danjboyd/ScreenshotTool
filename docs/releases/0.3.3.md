ScreenshotTool 0.3.3 can read the text in an image and redact the email addresses and phone numbers it finds. It also adds JPEG export, and fixes a set of Share and Take Screenshot problems.

## Upgrading

Use Check for Updates, or wait for the automatic check.

## Changes

- **Text in images (all platforms):** Edit ▸ Copy Text copies the text the image shows, and Edit ▸ Redact Emails and Phone Numbers covers the ones it finds (#278, #322). The text is read on your computer, and nothing is sent anywhere: macOS uses Vision and Windows uses Windows.Media.Ocr. On Linux, the commands appear when `tesseract` is installed, for example `sudo apt install tesseract-ocr`.
- **Save As (all platforms):** JPEG is offered alongside PNG (#277, #321)
- **Share (all platforms):** one share sheet at a time. A second Share click no longer opens a second sheet on top of the first (#316, #324, #334).
- **Share (macOS):**
  - Starting a second share while an AirDrop sheet is up, from the File menu or the toolbar, no longer stacks a second AirDrop sheet (#335, #336, #337).
  - When Share is folded into the toolbar's » menu, it's a Share submenu, as in File ▸ Share. It used to open an empty picker (#298, #324).
  - Cancelling AirDrop no longer reports "Shared with AirDrop" (#299, #324).
- **Take Screenshot (all platforms):** the window hides during the capture on macOS and Windows too, as it already did on Linux (#313, #317)
- **Take Screenshot (Linux):** cancelling GNOME's screenshot dialog no longer shows an error (#314, #319)
- **Take Screenshot (Windows):** cancelling the Snipping Tool no longer leaves Take Screenshot disabled for up to two minutes (#315, #318)
- **Windows:** ScreenshotTool can offer to open an image another app copies, such as a Win+Shift+S snip. It shows Open New Screenshot in the status bar. Turn it on in Preferences ▸ Workspace ▸ Offer to open screenshots copied in other apps (#275, #323).
- **Windows:** drag the image out of the Copy button into another app, for example the Desktop, a browser, Paint or Word (#276, #325)
- **Windows:** at 125% and 150%, text is evenly spaced. The status bar no longer reads "px ·PNG" (#306, #320).
- **Windows:** libs-back 0.32.0.5 and WinUITheme 0.1.0-alpha13 (#329)
- **Updates (Linux and Windows):** an install-failed alert no longer ends with a double period. This comes from gnustep-packager v0.1.4 (#328).

## Known issues

- **Linux:** the About panel can open behind the main window. Bring it forward from the Activities overview.
- **Windows:** Email reports that the share is done as soon as you click it, not when Outlook's message window returns. A failure later in Outlook may go unreported.
- **Linux on Wayland:** the share sheet's Copy writes only the X11 clipboard. The toolbar's Copy button writes to both clipboards.
- **Windows 11:** pressing Esc in Open With's chooser doesn't bring the share sheet back (libs-sharing#26).

The macOS app is ad-hoc signed and not notarized, so Gatekeeper asks before the first launch. See [Install ▸ macOS](https://github.com/danjboyd/ScreenshotTool#macos) in the README, or "Opening an unsigned app.txt" in the DMG. The Windows MSI is unsigned: click "More info → Run anyway" in Windows SmartScreen.
