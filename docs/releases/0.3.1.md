ScreenshotTool 0.3.1 fixes the rough edges in 0.3.0's Share and text tools.

## Upgrading

Use Check for Updates, or wait for the automatic check.

## Fixes

- **Share sheet (Linux and Windows):** a custom action with choices no longer looks like a set of duplicates. Each choice's tile reads, for example, "Send to Server" over "— home", with an icon. A name too long for its tile loses its middle ("Google…Drive") instead of being cut off at the edges (#279, #285)
- **Share sheet (Linux and Windows):** rclone tiles read "Link on <remote>", and after an upload the app says "Uploaded to <remote>; link copied". The sheet also:
  - is only as wide as its tiles;
  - closes when you go back to the window;
  - comes back if you cancel Save a Copy or Open With;
  - opens Save a Copy where you last saved a copy (#285)
- **Share sheet (Windows)**:
  - Open With shows the app chooser (it did nothing);
  - Save a Copy keeps the .png extension when you type a name without it;
  - Show in Folder opens Explorer with the shared copy selected, instead of This PC;
  - tiles widen to fit "Show in Folder" on one line (libs-sharing #22, #25, #291)
- **macOS:** a custom action from a Share menu no longer says "Shared with …" before it has run. It says how it went itself (#280, #282)
- **macOS:** Bold and Italic work with System Font (#286)
- **Linux:** with GNUstep's own menus, the menu is titled "ScreenshotTool" instead of "GSMainMenu" (#288)
- **Windows:** zoomed in, the image no longer smears from 300% or vanishes from 400%. As on Linux, the app now scales the visible part of the image itself, at every display scaling (#231, #289, #293)
- **Linux and Windows:** Open With ▸ ScreenshotTool opens the shared image. A new instance used to delete it at launch and report "Unable to Open Image" (#294)
- **Windows and Linux:** About shows the right version. That came with 0.3.0's packaging (gnustep-packager#32) (#194)

## Also

- New README screenshots on every platform, all marking up the same sample page (#283, #284, #287)

## Known issues

- **Windows:** Email reports that the share is done as soon as you click it, not when Outlook's message window returns. A failure later in Outlook may go unreported.
- **Linux on Wayland:** the share sheet's Copy writes only the X11 clipboard. The toolbar's Copy button writes to both clipboards.
- **Windows:** saving over an existing file, with Save As… or Save a Copy, doesn't ask first; the file is replaced without a warning (WinUI theme).
- **Windows 11:** pressing Esc in Open With's chooser doesn't bring the share sheet back (libs-sharing#26).
- **Windows, compact layout** (WinUIThemeMetrics=compact): long share tile titles can be clipped until WinUITheme's fix (plugins-themes-winuitheme#164) is in the bundled theme.

The Windows MSI and the macOS app are still unsigned. See "Opening an unsigned app.txt" in the DMG, and click "More info → Run anyway" in Windows SmartScreen.
