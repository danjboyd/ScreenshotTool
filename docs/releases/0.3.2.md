ScreenshotTool 0.3.2 gives the toolbar bigger icons and a smarter overflow menu, and brings the Windows and Linux themes up to date.

## Upgrading

Use Check for Updates, or wait for the automatic check.

## Changes

- **Toolbar (all platforms):** the icons are bigger: their glyphs fill about 85% of the icon instead of 62% (#301)
- **Toolbar in a narrow window (all platforms):** items go into the » menu in order of use, not from the end of the row (#303):
  - Undo and Redo go first; they're in the menus with shortcuts;
  - then custom actions, then Share and Save;
  - the tools, colour and Copy stay, and the window can't be made narrower than they need.

  On macOS this keeps Share out of the » menu, where it opened an empty picker (#298). On Linux and Windows it needs the bundled theme to support it. WinUITheme 0.1.0-alpha11 and Adwaita 0.1.0-alpha16, both in this release, do.
- **Windows:** WinUITheme 0.1.0-alpha11 (#300):
  - Save As… and Save a Copy ask before replacing an existing file (plugins-themes-winuitheme#168, a known issue in 0.3.1);
  - the toolbar is 40 pt tall, and the tool buttons are 40 pt wide. At 150% the narrowest window still fits on half of a 1920 px screen;
  - with WinUIThemeMetrics=compact, long share tile titles aren't clipped (plugins-themes-winuitheme#164, a known issue in 0.3.1).
- **Windows:** at 150%, the status bar's zoom label no longer draws over its old value (#290, #296)
- **Linux:** Adwaita 0.1.0-alpha16 (#305). Submenus line up with the item that opens them.
- **Linux and Windows:** a relative path on the command line opens the right file, for example `./ScreenshotTool.AppImage Pictures/shot.png` or `ScreenshotTool.exe docs\shot.png`. It used to look inside the app (gnustep-packager#63, #302)
- **Updates (Linux and Windows):** if an update fails to install, the app says so at its next launch. On Linux, View Changes and Skip This Version can be reached in the update window (#302)

## Known issues

- **Windows:** Email reports that the share is done as soon as you click it, not when Outlook's message window returns. A failure later in Outlook may go unreported.
- **Linux on Wayland:** the share sheet's Copy writes only the X11 clipboard. The toolbar's Copy button writes to both clipboards.
- **Windows 11:** pressing Esc in Open With's chooser doesn't bring the share sheet back (libs-sharing#26).
- **macOS:** Share… in the toolbar's » menu opens an empty picker (#298). Since this release Share goes into » only in a very narrow window. Use File ▸ Share instead.
- **macOS:** cancelling AirDrop still reports "Shared with AirDrop" (#299).

The Windows MSI and the macOS app are still unsigned. See "Opening an unsigned app.txt" in the DMG, and click "More info → Run anyway" in Windows SmartScreen.
